## Steps

1. **DAL** — `IBookingRepository.HasOverlapAsync(guideId, startUtc, endUtc, excludeId, ct)` + `BookingRepository`: `AnyAsync` over `GuideProfileId == guideId`, status Accepted or Confirmed, `Id != excludeId`, overlap formula. Tracked `GetByIdAsync` is reused to load the booking for the change. **Seed:** add a Pending request for Omar overlapping his Accepted booking (Emma's), and Mona to `DevLoginController`.
2. **BLL** — `IBookingService.AcceptAsync(guideUserId, bookingId, ct)`: profile via `GetByUserIdAsync` (Approved, else `GuideNotApproved`); booking via `GetByIdAsync` (missing or other guide → `NotFound`); expired Pending → `InvalidStatusChange` ("This request has expired"); `HasOverlapAsync` → `Overlap`; `_stateMachine.Apply(booking, Accepted, Actor.Guide, now)`; `SaveChangesAsync`; concurrency conflict → `Result.Fail(ErrorCodes.Concurrency, "This booking was changed by someone else. Refresh and try again.")`. Inject `IBookingStateMachine`. **List warning:** `Domain/BookingOverlap.Overlaps(a, b)` (the formula); `GetForGuideAsync` sets `BookingDto.OverlapsWithRef` on Pending rows from the already-loaded list (no extra query).
3. **PL** — `BookingRequestsController.Accept(int id, ct)` `[HttpPost]`: call service, `TempData` success ("Request accepted. The tourist must pay before …") or error message, `RedirectToAction(Index)`.
4. **View** — on Pending cards replace the disabled Accept button with a `<form method="post" asp-action="Accept" asp-route-id>` button; overlap warning line "Overlaps booking #TG-xxxx — accepting will be refused" (`GuideBookingItemViewModel.OverlapsWithRef`); flash message block at the top (success / error styles from `Bookings.css`). Reject stays disabled until 2.7.c.
5. **Build + manual check** — `dotnet build`; DevLogin as Omar: accept John's Pending → Accepted with deadline; seed or create an overlapping Pending and try to accept → refused; a second guide posting Omar's id → refused; double-submit / two tabs → one wins.
