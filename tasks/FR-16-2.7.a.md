## Steps

1. **DAL** — `IBookingRepository.GetForGuideAsync(guideId, ct)` in `ISpecificRepositories.cs` + `BookingRepository`: `AsNoTracking`, filter `GuideProfileId`, include `Tourist` (name, country) and `GuideProfile` (`TimeZoneId`); order Pending first by `StartUtc`, then rest by `CreatedAtUtc` desc (see Q3).
2. **BLL** — extend `BookingDto` only if a field is missing (tourist name/country); add mapping lines to `BookingMappingProfile`; `IBookingService.GetForGuideAsync(guideUserId, ct)`: profile via `GetByUserIdAsync` (none → `Result.Fail(NotFound)`), set `CanAccept`/`CanReject` (Pending) and `AutoCancelAtUtc` with `BookingRules`/`BookingJobOptions` — no new numbers.
3. **PL** — `Areas/Guide/Controllers/BookingRequestsController.Index` (`[Area("Guide")]`, `[Authorize(Roles = Roles.Guide)]`, `ICurrentUserService`, ct); `GuideDashboardViewModel` + `GuideBookingItemViewModel` (local date/time text via `TimeZoneHelper`, status note, flags) in `GuideViewModelProfile`.
4. **View** — `Areas/Guide/Views/BookingRequests/Index.cshtml` from screen 3: status chips with counts (client-side filter, as 2.8.a), card per booking (badge, tourist, date line, type/hours/days, price line, deadline on Accepted, auto-cancel note on Pending), Accept/Reject rendered disabled until 2.7.b/c, empty state; `_ViewImports`/`_ViewStart`; nav link "Requests" for guides.
5. **Build + manual check** — `dotnet build`; demo seed: a guide with bookings in all six statuses, a second guide, a tourist and the admin for access checks.
