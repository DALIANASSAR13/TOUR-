## Steps

1. **BLL** — `IBookingService.WithdrawAsync(touristId, bookingId, ct)`: load → not found / not owner → same "not found" fail → `CanChange(status, Cancelled, Actor.Tourist)` → `Apply` (sets `CancelledAtUtc`, `WithdrawnByTourist`) → `SaveChangesAsync` → catch concurrency → `Result.Fail`. Reuse the state-machine/concurrency helpers from 2.7.b/c; no copied messages.
2. **PL** — Tourist `BookingsController.Withdraw(int id, ct)` `[HttpPost]`: call service, TempData "Booking #TG-xxxx withdrawn." / error, PRG to `Index`.
3. **View** — `Areas/Tourist/Views/Bookings/Index.cshtml`: enable the disabled Withdraw button from 2.8.a as a POST form with the same inline `<details class="mb-confirm">` confirm as 2.7.c; show the flash message; Cancelled card note "You withdrew this booking."
4. **Build + manual check** — `dotnet build`; DevLogin as Emma: withdraw a Pending and an Accepted; try a Confirmed id by hand-crafted POST; John tries Emma's id; guide accepts in another tab while Emma withdraws.
