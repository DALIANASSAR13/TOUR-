## Decisions (answered)

1. **Average:** recomputed from all of the guide's reviews inside the transaction (not incremental), to avoid rounding drift in `decimal(3,2)`. This needs one query that is **not in the AGENTS.md catalog**: `IReviewRepository.GetRatingTotalsAsync(guideId, ct)` → `(int Count, int Sum)`. Team must accept it (add to "Decisions log" and the catalog).
2. **Form:** a separate page `Tourist/Reviews/Create` (GET shows the booking summary + form, POST saves). The disabled "Write a review" button on My Bookings becomes a link to it. No modal.

## Steps

1. **DAL** — `IReviewRepository.ExistsForBookingAsync(bookingId, ct)` and `GetRatingTotalsAsync(guideId, ct)` (read-only, no `SaveChanges`); implement in `ReviewRepository.cs`.
2. **BLL** — `DTOs/Review/CreateReviewRequest` (`BookingId`, `Rating`, `Comment`); `Validators/CreateReviewValidator` (rating `InclusiveBetween(MinRating, MaxRating)`, comment `MaximumLength(MaxCommentLength)`); `ReviewMappingProfile`: `CreateReviewRequest → Review` (copies `BookingId`, `Rating`, `Comment`; ignores the rest); `Services/Interfaces/IReviewService` + `Services/ReviewService` (`AddAsync`, `CanReviewAsync`); register `IReviewService` in `AddBusinessLogic`.
   `AddAsync` order: validator → load booking (missing or not owner → `NotFound`) → status `Completed` (else `InvalidStatusChange`) → `ExistsForBookingAsync` (else `AlreadyReviewed`) → transaction: add `Review` (`TouristId`, `GuideProfileId` from the booking, `CreatedAtUtc` from `TimeProvider`), save, recompute totals, update the guide's `AverageRating` (rounded to 2 decimals) and `ReviewCount`, save, commit. Guide profile is loaded tracked.
3. **PL** — `ViewModels/CreateReviewViewModel` (`BookingId`, `Rating` with `[Range(BookingRules.MinRating, BookingRules.MaxRating)]`, `Comment` with `[StringLength(BookingRules.MaxCommentLength)]`, plus read-only guide name and trip text for display); map in `TouristViewModelProfile`; `Areas/Tourist/Controllers/ReviewsController` (`Create` GET calls `CanReviewAsync`, else redirect with `BookingError`; `Create` POST); `Areas/Tourist/Views/Reviews/Create.cshtml` (star picker, validation partial); `css/Tourist/` only if the shared styles do not fit.
4. **View** — `Areas/Tourist/Views/Bookings/Index.cshtml`: replace the disabled button (lines 81–84) with `<a asp-controller="Reviews" asp-action="Create" asp-route-bookingId="@b.Id">`; `BookingsController` index already shows the flash messages (`BookingMessage`). This is M6's file: change only those lines and tell M6.
5. **Build + manual check** — `dotnet build` (no `dotnet` in the agent session, so run it on your machine); demo data: Emma, a Completed booking without a review.

## Acceptance criteria

- [ ] AC1 (R1, R5): Emma rates her Completed booking 4 stars with a comment → saved; flash "Thank you for your review."; My Bookings shows "Your rating" and no review button
- [ ] AC2 (R5, R9): rating 0 or 6, missing rating, or a comment over 1,000 characters → refused on client and server (forced POST) with a short English message; limits come from `BookingRules` only
- [ ] AC3 (R2): John posting a review for Emma's booking → "not found", nothing saved; Guide or Admin → access denied; anonymous → login
- [ ] AC4 (R3): POST for a Pending, Accepted, Confirmed, Rejected or Cancelled booking → refused, nothing saved; no review button on those cards
- [ ] AC5 (R4): second review for the same booking (second tab or forced POST) → "already reviewed" message; one row in `Reviews`
- [ ] AC6 (R6): after a review, the guide's `ReviewCount` is +1 and `AverageRating` equals the average of all that guide's ratings (2 decimals); a failure in the second save leaves no review (one transaction)
- [ ] AC7 (R7): no edit or delete action, route or button for reviews
- [ ] AC8 (R10): failures are `Result.Fail` (no exceptions for business cases); `TimeProvider` used; AutoMapper profile sets no date, id or rating totals
- [ ] AC9 (R11): GET `Create` for a booking that cannot be reviewed redirects with a message; POST has anti-forgery; the controller has no LINQ or claims
- [ ] AC10 (3.2.b): the new review and the new average appear on the guide's public page (`/Guides/Details/{id}#reviews`)
- [ ] AC11 (R13): signatures match the class diagram (`ct` added)
- [ ] `dotnet build` passes (only `NU1903`)

## Open questions

1. **`GetRatingTotalsAsync`** is a new repository method outside the catalog. Needs the team's OK and a line in `AGENTS.md` → Catalog (rule: change `AGENTS.md` only when the team changes a rule).
2. **Unique-index race** (two submits at the same moment): the pre-check catches almost all of them; the unique index stops the rest. Proposed: the global error page, not a special message. Confirm.
3. **`GuideProfile` has no `RowVersion`:** two different tourists reviewing the same guide at the same moment can both recompute from the same totals. Recomputing from all reviews inside the transaction makes the last commit correct. Confirm no `RowVersion` is wanted.
