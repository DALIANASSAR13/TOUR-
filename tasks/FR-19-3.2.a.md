## Decisions (answered)

1. **Average (changed by the team on 2026-11-13):** incremental, from the stored `AverageRating` and `ReviewCount`: `new = round((old × count + rating) / (count + 1), 2)`. No new repository method, so the AGENTS.md catalog is unchanged. Known trade-off: rounding drift over many reviews (the stored average is already rounded to 2 decimals).
2. **Form:** a separate page `Tourist/Reviews/Create` (GET shows the form, POST saves). The disabled "Write a review" button on My Bookings becomes a link to it. No modal. The form shows only the booking reference (`TG-0042`): a guide name or trip date would need a new service method or LINQ over DTOs in the controller, so it is left out unless the team wants `IReviewService.GetForReviewAsync`.
3. **One save, not an explicit transaction:** the review and the guide's new rating are written by a single `SaveChangesAsync`, which is already one database transaction (R6). `BeginTransactionAsync` is not needed.

## Steps

1. **DAL** — `IReviewRepository.ExistsForBookingAsync(bookingId, ct)` (read-only, no `SaveChanges`); implement in `ReviewRepository.cs`.
2. **BLL** — `DTOs/Review/CreateReviewRequest` (`BookingId`, `Rating`, `Comment`); `Validators/CreateReviewValidator` (rating `InclusiveBetween(MinRating, MaxRating)`, comment `MaximumLength(MaxCommentLength)`); `ReviewMappingProfile`: `CreateReviewRequest → Review` (copies `BookingId`, `Rating`, `Comment`; ignores the rest); `Services/Interfaces/IReviewService` + `Services/ReviewService` (`AddAsync`, `CanReviewAsync`); register `IReviewService` in `AddBusinessLogic`.
   `AddAsync` order: validator → load booking (missing or not owner → `NotFound`) → status `Completed` (else `InvalidStatusChange`) → `ExistsForBookingAsync` (else `AlreadyReviewed`) → add `Review` (`TouristId`, `GuideProfileId` from the booking, `CreatedAtUtc` from `TimeProvider`), update the tracked guide's `AverageRating` (incremental, rounded to 2 decimals) and `ReviewCount`, one `SaveChangesAsync`.
3. **PL** — `ViewModels/CreateReviewViewModel` (`BookingId`, `Rating` with `[Required]` + `[Range(BookingRules.MinRating, BookingRules.MaxRating)]`, `Comment` with `[StringLength(BookingRules.MaxCommentLength)]`, get-only `Reference` for display); map in `TouristViewModelProfile`; `Areas/Tourist/Controllers/ReviewsController` (`Create` GET calls `CanReviewAsync`, else redirect with `BookingError`; `Create` POST); `Areas/Tourist/Views/Reviews/Create.cshtml` (star picker, validation partial); `css/Tourist/` only if the shared styles do not fit.
4. **View** — `Areas/Tourist/Views/Bookings/Index.cshtml`: replace the disabled button (lines 81–84) with `<a asp-controller="Reviews" asp-action="Create" asp-route-bookingId="@b.Id">`; `BookingsController` index already shows the flash messages (`BookingMessage`). This is M6's file: change only those lines and tell M6.
5. **Build + manual check** — `dotnet build` (no `dotnet` in the agent session, so run it on your machine); demo data: Emma, a Completed booking without a review.

## Open questions

1. **Lost update without `RowVersion`:** `GuideProfile` has no concurrency token. Two tourists reviewing the same guide at the same moment can both read the same `ReviewCount`; the last save wins and one review is missing from the count and average. Rare for an MVP; fixing it needs a `RowVersion` column + migration. **Accepted by the team for now (incremental average chosen 2026-11-13).** Add to Known issues.
2. **Unique-index race** (two submits of the same booking at the same moment): the pre-check catches almost all of them; the unique index stops the rest and the global error page is shown. Confirm.
3. **Guide name on the form:** only the booking reference is shown. Add `IReviewService.GetForReviewAsync` (guide name, trip dates) if the team wants more.
4. **M6:** `Bookings/Index.cshtml` — the disabled review button became a link (4 lines). Tell M6.
